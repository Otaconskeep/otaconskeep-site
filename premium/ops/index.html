Sharing response protocol

  1. Detect: Webhook shows same License ID from distant IPs/timezones in a short window, or member reports a leak.
  2. Confirm: Message the original payer on Discord with License ID + times. Ask if they authorized the other unlocks.
  3. Contain: In premium.js set status: 'suspended' or 'revoked', rotate password/PIN hashes, redeploy. Suspended seats fail unlock with a clear message.
  4. Resolve: If payer was compromised, re-issue new credentials, keep License ID or bump suffix. If intentional sharing, revoke; they can buy a new seat.
  5. Record: Update paymentRef / notes with the incident date so the ledger stays honest.

Issuing a new paid seat

  1. Confirm BMC payment (amount, name/note, date).
  2. Pick access name (A-Z0-9). Generate password + 4-digit PIN.
  3. Add hashes to USERS and a row to LICENSES with licenseId, paymentRef (e.g. BMC #1234 · $20 · 2026-09-17), seats: 1, status: 'active'.
  4. Commit, deploy, DM credentials + License ID. Never post secrets in public Discord.
