Otacon does not install or configure an LLM for you. To chat with an agent, install Ollama separately and pull the model tier Otacon recommended. Its default provider talks to Ollama automatically once it's running. Voice synthesis, speech-to-text, and image/video generation follow the same pattern: the routing exists, but each needs its own provider connected (see status below).

Architecture

Built on a resource arbiter, not a script

User→ Agent (identity · memory · voice)→ Capability Router→ LLM / TTS / STT Providers

A provider-neutral resource arbiter sits beneath capability routing: workloads request logical CPU/RAM/GPU/VRAM and receive leases that respect placement, priority, and health, rather than agents hardcoding device indexes. Idle model residency can be reclaimed gracefully while active work is protected. Per-voice synthesis settings are configured individually rather than one global profile applied to every voice. This is the same architecture that, at full scale in the private Keep, extends to media, home, and multi-node GPU orchestration. See The Keep.

Install

Install once. Forget it.

Pick your OS below. Either path ends the same way: Otacon installed as a real background service, set to start itself every time this machine turns on. No terminal to reopen, no server to remember to start.

🪟 Windows

⭳ Download Windows Installer

Double-click it. It sets up WSL2 and Ubuntu automatically if they're not already there, walks you through the one unavoidable manual step (a restart and/or a one-time Ubuntu username/password, Microsoft's own requirement, not something any script can skip), then finishes on its own. You never need to open Ubuntu, WSL, or a terminal again after this.

🐧 Linux (Ubuntu/Debian, or already inside WSL)

curl -fsSL https://raw.githubusercontent.com/Otaconskeep/otacons-ai-ecosystem/main/install_otacon.sh | bash

First run takes 10–30 minutes and asks for your sudo password once. Installs itself as a systemd service, enabled to survive reboots and restart itself if it ever crashes.

✓ When it's done

Otacon is ready. Open it any time at:

Open Otacon →

Connect an LLM to actually chat: install Ollama and pull the model tier Otacon recommended during install. Otacon's default provider looks for it at 127.0.0.1:11434 automatically. No config editing needed.

Advanced: LAN access, repair, uninstall, and other options

Use Otacon from another device on your network

By default Otacon only answers on this machine. To reach it from your phone or another computer, find this PC's LAN IP (ip addr inside Ubuntu, or your router's device list) and visit http://<that-ip>:5757 instead.

Repair

Something not starting right? Just run install_otacon.bat (or install_otacon.sh) again. It re-checks and re-creates the auto-start service and logon task if either is missing, without resetting your existing install or data.

Uninstall auto-start only

Run uninstall_otacon.bat (Windows). It removes the logon task and the systemd service only. Your Ubuntu environment, install folder, and data are untouched.

Optional environment variables (set before running install_otacon.sh)

VariableDefaultWhat it changes
OTACON_INSTALL_DIR~/otacon-ai-ecosystemWhere Otacon gets installed
OTACON_BUILD_NATIVE1Set to 0 to skip building the native .deb app
OTACON_INSTALL_DEB0Set to 1 to also install the built .deb automatically
OTACON_LAUNCH_WIZARD1Set to 0 to skip auto-launching the service at the end
OTACON_INSTALL_STT0Set to 1 to install optional Faster-Whisper speech-to-text
OTACON_RUN_TESTS1Set to 0 to skip the self-test suite (faster, less safe)
OTACON_INSTALL_VOICE_TRAINER0Set to 1 to also install Genome Voice Trainer (GPU Piper) in the same run
Requires sudo to install a handful of system packages (build tools, Python, WebKit libs) and to register the systemd service. The script explicitly refuses to run as the root user itself.
Also detects your GPU (if NVIDIA), recommends qwen2.5:7b at 8GB+ VRAM or qwen2.5:1.5b otherwise, and falls back to CPU cleanly if no GPU is present.

Voice Training

Genome Voice Trainer — one-click GPU Piper cloning

Train a custom Piper voice on your NVIDIA GPU, then plug it into Otacon agent voice profiles. The installer handles Python, Docker, WSL on Windows, GPU lookup, the NVIDIA Container Toolkit, the CUDA training image, and a simple local status UI. Training is GPU-only on purpose: CPU torch was the silent failure mode we closed.

✓ One click, forget it

  • ✓ ASCII Otacon-style installer with interactive menu
  • ✓ Detects NVIDIA GPU via nvidia-smi and refuses to pretend CPU is fine
  • ✓ Builds piper-voice-trainer:gpu and verifies CUDA inside the container
  • ✓ Local status UI at http://127.0.0.1:8765
  • ✓ Hooks into Otacon Core: OTACON_INSTALL_VOICE_TRAINER=1

  1. Standalone (voice trainer only)

    curl -fsSL https://raw.githubusercontent.com/Otaconskeep/otacon-voice-trainer/main/install_voice_trainer.sh | bash

  2. With Otacon Core in one shot

    OTACON_INSTALL_VOICE_TRAINER=1 curl -fsSL https://raw.githubusercontent.com/Otaconskeep/otacons-ai-ecosystem/main/install_otacon.sh | bash

  3. Windows

    Use install_voice_trainer.bat from the repo — it bootstraps WSL and hands off to the Linux installer.

Requires an NVIDIA GPU with working drivers. The pipeline refuses CPU training so you do not burn hours on a silent dead-end.
Write-up (what broke, why :gpu exists, how Genome uses it): docs/WRITEUP.md on GitHub.
