What the Hell Is Linux?

Linux isn't one operating system you learn. It's a set of common foundations, with different distributions making different choices for different jobs.

That single idea explains why Mint, Ubuntu, Fedora, Bazzite, Arch, Omarchy, and Proxmox can all honestly call themselves "Linux" while solving completely different problems — and it's the idea this whole course is built around.

00 // Why start here

Most people never learn what a "distro" actually is

They just get told "install Ubuntu" or "install Mint" and never find out why there are 500 other options, or why a tutorial written for Fedora breaks on Debian. This module fixes that in ten short lessons — no terminal required yet. By the end you'll be able to look at any distro's homepage and immediately place it on the map: what it's built on, who it's for, and what it trades away to get there.

End goal of the full course: comfortably choose a distro, use the terminal, administer a Linux machine, troubleshoot it, and understand why Mint, Bazzite, Omarchy, Ubuntu/Debian, and Proxmox can all be "Linux" while serving very different purposes.

01 // The big picture

One kernel. Hundreds of distributions.

Every distribution you'll ever hear about — Mint, Ubuntu, Proxmox, Arch, Omarchy, Fedora, Bazzite — sits on top of the same Linux kernel. What makes them different isn't the engine, it's everything built around it: the package manager, the default apps, the release cadence, the desktop, and the project's actual goal.

This isn't a strict "reskin" tree — it's a map of inheritance: what base a project builds on, which repositories it draws from, and which desktop and goals it wraps around that base. Lesson 3 unpacks exactly how that inheritance works.

02 // The 10 lessons

Lesson-by-lesson

Every lesson is short, plain-language, and builds toward the same skill: being able to explain why a distro exists, not just its name.

Lesson 1

What is Linux?

Linux is a free, open-source kernel — the core program that talks to your hardware, manages memory, and decides which process gets the CPU next. On its own it's not something you "use"; it's the engine everything else sits on top of.

Lesson 2

Kernel vs. operating system vs. distribution

Kernel → the engine. Operating system → kernel + the tools needed to actually do anything (shell, libraries, init system). Distribution → a complete, ready-to-install package of an OS, curated by a specific project with its own defaults and philosophy.

Lesson 3

Why are there 500 Linux distributions?

Because the kernel and most of the software underneath are free to take and rebuild. Projects fork a base, add their own package manager or desktop, target a specific audience (gamers, servers, beginners, tinkerers), and ship it under a new name. That's the whole tree from Lesson 1, explained.

Lesson 4

GNU/Linux and open source

Most of the command-line tools and libraries around the Linux kernel come from the GNU Project — which is why purists say "GNU/Linux." Open source means the source code is public, so anyone can inspect it, modify it, and redistribute it, which is the entire reason so many distros can exist in the first place.

Lesson 5

Linux vs. Windows vs. macOS

Windows and macOS are closed, vendor-controlled, and built for a single "one true way" experience. Linux is open, and it hands you the choice of kernel config, desktop, package manager, and philosophy — more control, more responsibility, and a steeper (but optional) learning curve.

Lesson 6

Desktop environment vs. distro

The distro is the whole package; the desktop environment (Cinnamon, GNOME, KDE, Hyprland) is just the visual/window-management layer on top of it. The same distro can often run several different desktops — and the same desktop can show up on totally unrelated distros.

Lesson 7

Package manager vs. app store

An app store is a curated storefront. A package manager (apt, dnf, pacman) installs software from repositories and automatically resolves every dependency that software needs — which is why install commands differ by distro family, and why you usually can't just double-click a setup.exe.

Lesson 8

Rolling release vs. fixed release

Fixed-release distros (Ubuntu, Debian, Fedora) ship big versions on a schedule and hold packages steady in between. Rolling-release distros (Arch, Omarchy) push updates continuously, so you're always close to the newest software — at the cost of things occasionally breaking without warning.

Lesson 9

Stable vs. bleeding edge

"Stable" doesn't mean "doesn't crash" — it means packages are frozen and heavily tested before they ship, which is exactly what you want on a server. "Bleeding edge" trades that safety for the newest kernels, drivers, and features, which is exactly what you want on a daily gaming or dev desktop.

Lesson 10

Which Linux should I actually use?

Wrong question. The right question is "best for what?" — a beginner desktop, a gaming rig, a dependable server, a keyboard-driven workstation, a learning project, or a homelab hypervisor all have different right answers. See the picker below.
