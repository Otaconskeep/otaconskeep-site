Workbook page 1 — What you're going to learn

Understand how containers find each other — and the difference between localhost, LAN IP, published ports, and container DNS names.

In plain words: Apps on the same private Docker street can call each other by name. Your phone usually uses the house number (LAN IP) plus a door (port).
More detail: bridge vs user-defined bridge vs host vs macvlan/ipvlan — start with a user-defined bridge for ARR.

Reachability cheat sheet:
  localhost:9696        only on the host
  192.168.x.20:9696     from another LAN device
  prowlarr:9696         container-to-container on media_network

Workbook page 4 — Guided notes (from the lecture ideas)

  • Create media_network; attach Sonarr + Prowlarr.
  • Experiment: curl/wget from Sonarr container to http://prowlarr:9696.
  • Break/fix: disconnect Prowlarr from the network and diagnose.
In plain words: Same Docker network = same private hallway. Container names are room signs.
More detail: Publishing 9696:9696 opens a door from the LAN into that hallway.

Workbook page 5 — Windows / Linux baby-step lab

docker network create media_network
# In compose: networks: [media_network] on prowlarr + sonarr
# From host: curl -I http://127.0.0.1:9696
# From another container on media_network: wget -qO- http://prowlarr:9696 | head
In plain words: If container-name DNS fails, they are not on the same user-defined network.
More detail: Do not put the whole stack on host networking 'to make it easy' — that hides useful failures.
