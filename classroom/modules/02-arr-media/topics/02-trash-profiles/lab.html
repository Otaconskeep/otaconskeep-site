Hands-on

Guided lab

In plain words: Do these steps in order, one time, without skipping. Each step should leave proof you can show later.
More detail: If a step fails, stop and use Break/fix instead of inventing a new path.

Work in one app first (Sonarr or Radarr). Export/backup before edits. TRaSH Guides are a reference for intent—not a blind paste.

1

Export / back up current quality profiles.

Windows (CMD / PowerShell)
cd COMPOSE_DIR
# UI: Settings → General → Backup, download zip to a private folder
# Also copy config bind mount:
Copy-Item -Recurse .\sonarr\config $HOME\backups\sonarr-profiles-$(Get-Date -Format yyyyMMdd) -ErrorAction SilentlyContinue
Linux / macOS (Terminal)
cd COMPOSE_DIR
# UI backup zip AND:
mkdir -p ~/backups/profiles-$(date +%Y%m%d)
cp -a ./sonarr/config ~/backups/profiles-$(date +%Y%m%d)/sonarr 2>/dev/null || true
cp -a ./radarr/config ~/backups/profiles-$(date +%Y%m%d)/radarr 2>/dev/null || true
In plain words: Make a safety copy first so a mistake does not erase your work.
2

Record current state (workbook table).
For the profile you will change: allowed qualities, order, cutoff, upgrade allowed?, minimum Custom Format score, upgrade-until score, list of Custom Formats + scores.

In plain words: These rules grade releases so your apps pick the quality you actually want.
3

Optional API dump of profiles (redact; replace KEY/PORT):

Linux / macOS (Terminal)
curl -s "http://127.0.0.1:8989/api/v3/qualityprofile?apikey=YOUR_KEY" | head -c 400; echo
curl -s "http://127.0.0.1:8989/api/v3/customformat?apikey=YOUR_KEY" | head -c 400; echo
Windows (CMD / PowerShell)
curl.exe -s "http://127.0.0.1:8989/api/v3/qualityprofile?apikey=YOUR_KEY"
curl.exe -s "http://127.0.0.1:8989/api/v3/customformat?apikey=YOUR_KEY"
In plain words: Loopback talks only to this computer. Ping 127.0.0.1 to check the local IP stack.
4

Write the local requirement in one sentence (example: “Prefer 1080p WEB, reject incompatible HDR for this TV, allow upgrades until score ≥ X”).

In plain words: Do this step fully, then check that it worked before the next one. Focus: Write the local requirement in one sentence.
5

Import or create only the Custom Formats that match that sentence. Assign scores and write why each score exists.

In plain words: Do this step fully, then check that it worked before the next one. Focus: Import or create only the Custom Formats that match that sentence.
6

Set qualities, cutoff, min CF score, upgrade-until. Save the profile.

Interactive search a controlled monitored title. For ≥5 release candidates, record in the workbook:

release name | quality | CF score | preferred? | reason accepted/rejected
In plain words: Do this step fully, then check that it worked before the next one. Focus: Interactive search a controlled monitored title.
8

If ranking violates the written policy, change only one rule, save, repeat the five-candidate table.

9

Prove rollback: restore from the backup zip or copied config (app stopped if required), reopen profile UI, confirm original scores return.

Linux / macOS (Terminal)
docker compose stop sonarr
# restore config from ~/backups/... then:
docker compose start sonarr
docker compose logs --tail=50 sonarr

Break / fix

Break / fix

In plain words: Break one thing on purpose, watch the failure, then repair it.
More detail: Change only one variable at a time.

Break/fix

  1. Set an unreachable upgrade-until score; observe endless “not done” behavior; restore.

  2. Give a minor preference a higher score than a hard compatibility CF; observe bad ranking; restore.

  3. Temporarily remove an incompatible-HDR (or similar) CF; inspect newly eligible junk; restore.

  4. Restore backup and prove the five-candidate ranking matches the pre-change table.

In plain words: Make a safety copy first so a mistake does not erase your work.
Fix chart

Feedback / common mistakes

In plain words: These are the traps other students fall into. Check yourself against the list.
  • Mixing 1080p and 2160p goals without understanding quality ordering.
  • Copying scores from a guide without checking hardware compatibility.
  • Confusing minimum score with upgrade-until score.
  • Allowing DV profiles that produce bad playback on the household display chain.
  • Setting file-size limits that exclude every reasonable release.
  • Changing global profiles on a live library without a sample evaluation and backup.
In plain words: Make a safety copy first so a mistake does not erase your work.
