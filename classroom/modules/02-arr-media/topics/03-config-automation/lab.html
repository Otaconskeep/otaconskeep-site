Hands-on

Guided lab

In plain words: Do these steps in order, one time, without skipping. Each step should leave proof you can show later.
More detail: If a step fails, stop and use Break/fix instead of inventing a new path.

Pick one supported sync approach you actually run (recyclarr, Notifiarr profiles, manual export/import, or another maintained tool). Pin its version. Use a disposable test profile, not your only production profile.

1

Create a disposable test profile in Sonarr or Radarr (UI). Name it otacon-test-profile. Record initial qualities/cutoff/CF list.

In plain words: Do this step fully, then check that it worked before the next one. Focus: Create a disposable test profile.
2

Pin the tool version and show it.

Windows (CMD / PowerShell)
# Example if using recyclarr via docker:
docker compose exec recyclarr recyclarr --version
# Or local binary:
recyclarr --version
Linux / macOS (Terminal)
docker compose exec recyclarr recyclarr --version 2>/dev/null || recyclarr --version
command -v recyclarr; type recyclarr
In plain words: Compose is the recipe file that starts and stops your app group together.
3

Point config at the test profile only. Validate / dry-run without applying.

Linux / macOS (Terminal)
# Pattern — exact subcommands depend on current tool docs:
recyclarr config list
recyclarr sync --dry-run
# or: docker compose exec recyclarr recyclarr sync --dry-run
Windows (CMD / PowerShell)
docker compose exec recyclarr recyclarr sync --dry-run
In plain words: Compose is the recipe file that starts and stops your app group together.
4

Capture the proposed diff/log to a private file (redact secrets):

Linux / macOS (Terminal)
recyclarr sync --dry-run 2>&1 | tee ~/backups/recyclarr-dryrun-$(date +%Y%m%d).log | tail -n 40
In plain words: Sync means copy the settings from one app into another so they match.
5

Apply once to the test profile. Re-open the UI and compare to the dry-run.

In plain words: Do this step fully, then check that it worked before the next one. Focus: Apply once.
6

Apply a second time (idempotency). Expect no duplicate CFs / no destructive churn. Save both logs.

In plain words: Do this step fully, then check that it worked before the next one. Focus: Apply a second time (idempotency).
7

Create intentional drift: manually change one CF score in the test profile UI.

In plain words: Do this step fully, then check that it worked before the next one. Focus: Create intentional drift:.
8

Dry-run again and confirm the tool detects the drift. Decide: overwrite from source of truth, or update the declaration.

In plain words: Do this step fully, then check that it worked before the next one. Focus: Dry-run again.
9

Apply the chosen resolution. Re-run Class 6’s five-candidate behavior check on a controlled title.

In plain words: Do this step fully, then check that it worked before the next one. Focus: Apply the chosen resolution.
10

Rollback proof: restore ARR backup from Class 6/7 start; confirm test profile gone or restored; record commands/UI steps used.

Linux / macOS (Terminal)
docker compose stop sonarr
# restore config backup
docker compose start sonarr
curl -sf "http://127.0.0.1:8989/ping" && echo SONARR_UP
In plain words: Loopback talks only to this computer. Ping 127.0.0.1 to check the local IP stack.
Break / fix

Break / fix

In plain words: Break one thing on purpose, watch the failure, then repair it.
More detail: Change only one variable at a time.

Break/fix

  1. Run sync twice; prove idempotency in logs.

  2. Point two tools at the same profile (or simulate conflicting ownership)—observe fight; pick one owner.

  3. Break YAML/config syntax; show validator failure; fix.

  4. Restore backup; prove scores match the pre-lab export.

In plain words: Make a safety copy first so a mistake does not erase your work.
