Path B: Same LAN vs via gateway

In plain words: Do this carefully, then check that it worked before moving on. (Path B: Same LAN vs via gateway)
1

Same-network test: ping another LAN host; expect success (firewall permitting).

In plain words: Ping asks “are you reachable?” with a small echo packet. First tool when something seems offline.
2

Off-network test: ping 1.1.1.1 (or another known Internet IP). Expect success only if WAN works.

Linux / macOS (Terminal)
ping -c 3 1.1.1.1
traceroute -n 1.1.1.1 | head
# First hop should be your default gateway on a normal home setup
ip route | awk '/default/ {print}'
Windows (CMD / PowerShell)
ping -n 3 1.1.1.1
tracert -d 1.1.1.1
# First hop should be your Default Gateway
In plain words: The gateway is your router’s address on the LAN, the courier when the destination is not on your street.
3

Workbook: “First hop to the Internet was ____ (gateway). Local NAS ping did / did not need that hop for delivery decision.”

Path C: Usable-address math on your `/24`

In plain words: Do this carefully, then check that it worked before moving on. (Path C: Usable-address math on your that command)
1

If your mask is 255.255.255.0, compute:
- network address
- broadcast address
- theoretical host count (254)
- practical leftover after gateway (document your gateway IP)

In plain words: The broadcast address talks to every host on that subnet. Do not assign it to a normal device.
2

Optional stretch: on the router admin UI (screenshot secrets removed), note DHCP pool start/end. Compare pool size to your math.

In plain words: DHCP is how most home devices get an IP automatically from the router.
3

Static caution (do not break production): pick an unused address inside the subnet but outside the DHCP pool if you later static a lab VM. Record the choice; do not implement on a critical host until Class 1/Proxmox needs it.

In plain words: Proxmox is a Type 1 hypervisor you install on dedicated hardware and manage in a web browser.

Path D: Classes, loopback, and ping

In plain words: Loopback talks only to this computer. Ping 127.0.0.1 to check the local IP stack.
1

Classify your LAN IP by first octet using the A–E chart. Write: class letter, default classful mask, and your actual mask. Are they the same? (Most home LANs are Class C looking with a /24 mask, or Class A looking 10.x with a classless /24.)

In plain words: Old IPv4 classes A–C each had a default mask size. Learn the chart for exams; real labs use classless masks (CIDR).
2

Workbook contrast: one row for “classful default size,” one row for “my real network size.” One sentence: “Classful told me _; classless/mask told me _.”

In plain words: Old IPv4 classes A–C each had a default mask size. Learn the chart for exams; real labs use classless masks (CIDR).
3

In plain words: Loopback talks only to this computer. Ping 127.0.0.1 to check the local IP stack.
4

Break / fix

Break / fix

In plain words: Break one thing on purpose, watch the failure, then repair it.
More detail: Change only one variable at a time.

Break/fix

  1. Disconnect Wi-Fi / unplug Ethernet → ipconfig / ip addr loses address or shows disconnected → restore → address returns (DHCP) or static returns.

  2. Wrong mental model: pretend a host 10.0.0.5 is “local” to your 192.168.1.0/24 without a router, explain why the mask says no.

  3. Gateway down simulation (lab only): if you can safely shut WAN on a test router, confirm LAN pings still work while 1.1.1.1 fails, proves local vs remote paths.

  4. Class vs mask: take a 10.x address with mask 255.255.255.0 and explain to a partner why calling it “a Class A network of 16 million hosts” would be wrong for your LAN.

  5. Loopback vs LAN: with Wi-Fi off, confirm ping 127.0.0.1 still works while ping 1.1.1.1 fails, local stack vs Internet path.

In plain words: DHCP is how most home devices get an IP automatically from the router.

Feedback / common mistakes

In plain words: These are the traps other students fall into. Check yourself against the list.
  • Mixing up private LAN IP with public WAN IP.
  • Calling every dotted number “the IP” and ignoring mask/gateway.
  • Assuming all LANs are 192.168.1.0/24.
  • Assigning .0 or .255 to a host on a /24.
  • Duplicating an IP already leased by DHCP.
  • Debugging Docker DNS before confirming the host even has a gateway.
  • Treating classful defaults as how the Internet still assigns every network (it does not, CIDR/classless won).
  • Putting a Class D/E or 127.x address on a lab host “because the chart had free numbers.”
  • Confusing “4.3 billion total IPv4 values” with “4.3 billion free for my devices.”
In plain words: An IP address is how devices find each other on a network. The mask tells which part is the ‘street’ and which part is the ‘house number.’
