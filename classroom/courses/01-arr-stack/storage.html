Create the /data layout

Show steps for: Change path

What you are learning

One parent tree for torrents, usenet, and media so hardlinks and atomic moves work.

You should already have

  • Lesson 1.1
  • Docker works

New words

Bind mountHardlinkVolume

Picture

/data
├── torrents/{movies,tv,anime,music}
├── usenet/{incomplete,complete/...}
└── media/{movies,tv,anime,music}

Step 1 — Create folders on the host

Create the tree on the machine that will run Docker. Put it on the disk that holds media.

Windows
mkdir -p /data/{torrents/{movies,tv,anime,music},usenet/{incomplete,complete/{movies,tv,anime,music}},media/{movies,tv,anime,music}}
# If you cannot use /data on Windows/WSL, use e.g. /mnt/d/data and stay consistent in Compose.
Linux
sudo mkdir -p /data/{torrents/{movies,tv,anime,music},usenet/{incomplete,complete/{movies,tv,anime,music}},media/{movies,tv,anime,music}}
sudo chown -R "$USER:$USER" /data
In plain words: One closet for all boxes. Downloads and finished shows must share a filesystem parent.
More detail: TRaSH warns against separate /downloads + /movies mounts that Docker treats as different filesystems.

Step 2 — Start an ARR compose folder

Create ~/homelab/arr for Compose files we fill in next lessons.

Windows
mkdir -p ~/homelab/arr && cd ~/homelab/arr
Linux
mkdir -p ~/homelab/arr && cd ~/homelab/arr
services: {}
# We will add services lesson by lesson in this folder.
# Keep one compose project: ~/homelab/arr/docker-compose.yml
In plain words: This is the recipe binder for your media robots.
More detail: One project keeps networks and mounts consistent.
